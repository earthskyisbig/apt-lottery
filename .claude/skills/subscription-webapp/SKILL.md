# 청약 자격진단 웹앱 스킬

`02_analyst_summary.json`의 공고 데이터를 **HTML 안에 심고**, 매칭 엔진을 **브라우저 JS로 이식**해
사용자가 폼에 조건을 입력하면 즉시 맞춤 결과가 나오는 자기완결 웹앱을 만든다.

## 왜 정적 HTML + 브라우저 계산인가
- **서버 불필요** — 파일 하나만 열면 동작. 수강생이 환경 문제로 좌절할 지점이 없다.
- **Artifact 게시 가능** — 외부 의존 0이라 CSP 안전.
- **개인정보가 나가지 않는다** — 입력한 조건이 브라우저 밖으로 전송되지 않는다. `profile.yaml`을 만들지 않아도 된다.
- 트레이드오프: 실시간 재수집 불가. 공고 데이터는 빌드 시점 스냅샷이며, 갱신은 스크립트 재실행.

## 입력 → 출력
- 입력: `_workspace/02_analyst_summary.json` (필수)
- 출력: `reports/청약자격진단.html` (자기완결, 외부 의존 0)

## 실행 방법 — 번들 스크립트
```bash
python .claude/skills/subscription-webapp/scripts/build_webapp.py --workspace _workspace --out reports
```
스크립트가 하는 일: (1) 요약 JSON 로드 (2) 공고를 웹앱용으로 평탄화·중복제거 (3) 템플릿의 `__DATA__` 자리에 JSON 주입 (4) `reports/청약자격진단.html` 출력.

## 브라우저 매칭 엔진 (`subscription-match` 규칙의 JS 이식)
지식베이스 §3·§5·§8을 그대로 옮긴다. 규칙을 바꾸려면 **양쪽(스킬·JS)을 함께** 고친다.

### 가점 (공식 표, 84점 만점)
- 무주택기간: 1년 미만 2점, 이후 1년당 +2점, 15년 이상 32점 → `y<1 ? 2 : min(32, 2+2*floor(y))`
- 부양가족: 0명 5점, 1명당 +5점, 6명 이상 35점 → `min(35, 5+5*n)`
- 통장기간: 6개월 미만 1점, 6개월~1년 2점, 이후 1년당 +1점, 15년 이상 17점 → `y<0.5 ? 1 : y<1 ? 2 : min(17, 2+floor(y))`
- 배우자 통장 합산(§8-4): 민영 가점에만 `min(3, floor(배우자년))` 가산.

### 판정
- **무주택(§8-2 완화)**: 비아파트 보유해도 전용 85㎡↓ + 공시가 수도권 5억↓이면 무주택 취급.
- **국민 성향**: 월납입 25만↑ 또는 저축총액 2,000만↑ → 국민주택 1순위 후보. 아니면 민영.
- **추첨 우위**: 예상 가점 < 55 → 민영은 추첨제 중심.

### fit_score (0~100)
특공 자격 적중 +40 / 일반공급 경로 적합 +20 / 무순위 자격무관 +15 / 지역 적중 +15 / 전략 태그 +10 / 마감임박 +10 / 자격 불명확 −10.

## 정직성 규칙 (리포트와 동일)
- **추천 카드마다** 규제 면책을 붙인다: "전매제한 · 실거주의무 · 투기과열지구 지정 · 특공 소득/자산기준은 시점마다 바뀝니다 — 청약홈/뉴홈 공고 원문에서 최신 확인."
- 가점은 **추정**임을 명시(무주택기간·통장기간은 사용자 입력 근사).
- 자격을 단정하지 않는다 — "지원 가능 후보 + 원문 확인".
- 결과 0건이면 빈 화면 대신 **왜 0건인지**(지역·유형 필터 때문인지) 안내한다.
- 데이터 스냅샷 기준일(`report_date`)을 항상 노출한다. 오래된 데이터를 최신인 양 보이지 않게.
