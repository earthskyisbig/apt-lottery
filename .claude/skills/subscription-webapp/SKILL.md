# 청약 자격진단 웹앱 스킬

`02_analyst_summary.json`의 공고 데이터를 **HTML 안에 심고**, 매칭 엔진을 **브라우저 JS로 이식**해
사용자가 폼에 조건을 입력하면 즉시 맞춤 결과가 나오는 자기완결 웹앱을 만든다.

## 왜 정적 HTML + 브라우저 계산인가
- **서버 불필요** — 파일 하나만 열면 동작. 수강생이 환경 문제로 좌절할 지점이 없다.
- **Artifact 게시 가능** — 외부 의존 0이라 CSP 안전.
- **개인정보가 나가지 않는다** — 입력한 조건이 브라우저 밖으로 전송되지 않는다. `profile.yaml`을 만들지 않아도 된다.
- 트레이드오프: 실시간 재수집 불가. 공고 데이터는 빌드 시점 스냅샷이며, 갱신은 스크립트 재실행.

## 입력 → 출력
- 입력: `_workspace/02_analyst_summary.json` (필수)
- 출력: `reports/청약자격진단.html` (자기완결, 외부 의존 0)

## 실행 방법 — 번들 스크립트
```bash
python .claude/skills/subscription-webapp/scripts/build_webapp.py --workspace _workspace --out reports
```
스크립트가 하는 일: (1) 요약 JSON 로드 (2) 공고를 웹앱용으로 평탄화·중복제거(주택형은 요약만) (3) `competition[]`을 지역별 근거 데이터 `results`로 압축 (4) 템플릿의 `__DATA__` 자리에 JSON 주입 (5) `reports/청약자격진단.html` 출력.

## 브라우저 매칭 엔진 (`subscription-match` 규칙의 JS 이식)
지식베이스 §3·§5·§8을 그대로 옮긴다. 규칙을 바꾸려면 **양쪽(스킬·JS)을 함께** 고친다.

### 가점 (공식 표, 84점 만점)
- 무주택기간: 1년 미만 2점, 이후 1년당 +2점, 15년 이상 32점 → `y<1 ? 2 : min(32, 2+2*floor(y))`
- 부양가족: 0명 5점, 1명당 +5점, 6명 이상 35점 → `min(35, 5+5*n)`
- 통장기간: 6개월 미만 1점, 6개월~1년 2점, 이후 1년당 +1점, 15년 이상 17점 → `y<0.5 ? 1 : y<1 ? 2 : min(17, 2+floor(y))`
- 배우자 통장 합산(§8-4, 청약홈 원문 "0~2년 이상"): 1년 미만 1 · 1~2년 2 · 2년↑ 3점 → `y<=0?0 : y<1?1 : y<2?2 : 3`.

### 1순위·특공 자격 (청약홈 청약자격·특별공급·용어설명 원문, 2026-09-05 대조)
- 규제 여부 = 공고 `regulation.speculation_zone||adjusted_area`(API 또는 주소 폴백). 국민 1순위: 가입 ≥ 규제 2년/비규제 1년 **및** 납입 ≥ 24/12회. 민영 1순위: 가입 ≥ 2/1년 + 예치금 ≥ 기준표(거주지 `resid` × 공고 최대 면적: 서울 300/600/1000/1500 · 광역시 250/400/700/1000 · 기타 200/300/400/500).
- 규제지역 강등: 세대주 아님(`household=무주택세대원`) 또는 `won5y` → 2순위. 통장 `없음`이면 일반공급 불가. `청약부금`은 85㎡ 초과 전용 단지 제외.
- 유주택: 국민주택 제외(무주택세대구성원 한정). 민영은 추첨제 후보로 유지하되 `다주택` + (규제지역 또는 `regulation.public_housing_zone`) → 2순위.
- 특공 공통: 통장 6개월↑. 다자녀 = 미성년 2명↑(6회↑). 노부모 = 세대주만. 생애최초 = 소득세 5년↑(`taxYears`), 국민·공공은 저축 600만↑, 공공은 1인가구 불가. 청년 = 공공주택만. **노부모·생초·신생아는 1순위 전제 + 규제지역 5년 내 당첨 세대 불가**. 공공 신혼 = 7년 이내 또는 `자녀6세이하`·`한부모`. 오피스텔 특공 없음, 공공임대는 배정 있는 유형만(순위 소득 100/110/120%).
- **소득 단계**(`INCOME_RULES`, 2025 도시근로자 표 `INCOME100`): `incomeWon`(만원)·`hh`(3/4/5)·`dual`·`relax`(2023.3.28↑ 자녀 +20%p)로 유형×민영/국민/공공별 우선/일반/추첨/초과. 초과면 경로 제거. 미입력 시 `income` 이분법 근사("추정").
- **잔여세대**: 임의공급 = 유주택 가능. 무순위(`house_secd`에 '불법' 없음) = 유주택이면 카드 제외, 규제면 재당첨제한 경고. 불법행위재공급 = 일반은 세대주만.
- 민영 추첨제 비율(`lotteryShare`): 규제·공공주택지구 60↓ 60% / 60~85 30% / 85↑ 20%(청약과열 50%), 비규제 85↓ 60%·85↑ 100%. 공공주택 국민 일반공급 + 신생아 → 우선공급 50% 안내.

### 판정
- **무주택(§8-2 완화)**: 비아파트 보유해도 전용 85㎡↓ + 공시가 수도권 5억↓이면 무주택 취급.
- **국민 성향**: 월납입 25만↑ 또는 저축총액 2,000만↑ → 국민주택 1순위 후보. 아니면 민영.
- **추첨 우위**: 예상 가점 < 55 → 민영은 추첨제 중심.

### 통계 연동 (2026-09 · analyst 확장 필드)
- **국민/민영**: 공고 `house_dtl`(API 값)을 우선, 없을 때만 통장 성향 추정.
- **특공 배정 확인**: `models[].special`이 있으면 내 세대유형 배정세대가 0인 경로는 제외(+5 확인 가산). 청년·신생아는 `is_public` 공공주택만.
- **선호 면적** 폼(59/74/84/100+): `areas`가 있는 공고만 버킷(57~72→59, 72~83→74, 83~100→84, 100+)으로 거른다. 없으면 `면적 미상` 태그로 남긴다.
- **빈집털이 신호**: `strategy_signals`(타워형·뒷알파벳·애매평형·소수세대) → 태그 +10, 어느 주택형인지 why에 명시. 신호일 뿐 판정 아님.
- **규제 플래그**: `regulation.speculation_zone/adjusted_area` → "투기과열/조정대상" 태그 −5, `price_cap` → "상한제" 태그. 원문 확인 문구는 그대로.
- **근거 데이터** `DATA.results`(접수 종료 단지 결과): 같은 지역 APT 최근 8건에서 내 특공 유형의 평균 경쟁률·미달 건수, 최저당첨가점 범위 vs 내 예상 가점을 카드 하단 "근거"로 노출. 미달 경향 +10, 가점 범위 내 +5.
- 카드에 분양가(만원→억)·전용면적 표시.

### fit_score (0~100)
특공 자격 적중 +40(배정 확인 +5) / 일반공급 경로 적합 +20 / 무순위 자격무관 +15 / 지역 적중 +15 / 면적 적중 +15 / 전략 태그(소수세대·빈집털이) +10 / 마감임박 +10 / 근거상 미달 경향 +10 / 가점 범위 내 +5 / 자격 불명확 −10 / 규제지역 −5.

## 정직성 규칙 (리포트와 동일)
- **추천 카드마다** 규제 면책을 붙인다: "전매제한 · 실거주의무 · 투기과열지구 지정 · 특공 소득/자산기준은 시점마다 바뀝니다 — 청약홈/뉴홈 공고 원문에서 최신 확인."
- 가점은 **추정**임을 명시(무주택기간·통장기간은 사용자 입력 근사).
- 자격을 단정하지 않는다 — "지원 가능 후보 + 원문 확인".
- 결과 0건이면 빈 화면 대신 **왜 0건인지**(지역·유형 필터 때문인지) 안내한다.
- 데이터 스냅샷 기준일(`report_date`)을 항상 노출한다. 오래된 데이터를 최신인 양 보이지 않게.
