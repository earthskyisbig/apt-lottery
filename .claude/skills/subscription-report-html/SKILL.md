# 청약 주간 리포트 HTML 스킬

`02_analyst_summary.json`을 읽어 비전문가도 30초 안에 파악하는 주간 리포트를 만든다.

## 입력 → 출력
- 입력: `_workspace/02_analyst_summary.json`
- 출력: `reports/청약리포트_{report_date}.html` (자기완결, CSS 인라인, 외부 의존 0)

## 섹션 순서 (중요도 = 배치 순서)
사용자가 놓치면 안 되는 것부터 위로.

0. **🎯 내 조건 맞춤** (`_workspace/03_match_personal.json`이 있을 때만, 최상단): 프로필 요약(주택수·세대유형·예상가점·성향) + `top_matches`를 fit_score 순 카드로. 각 카드에 지원경로(특공/일반/무순위)·전략 태그·D-day·`why`·`confirm`(원문 확인 사항). `simultaneous_groups`(동시분양 택1) 안내. 프로필이 없으면 이 섹션 대신 "profile.yaml을 세팅하면 내 조건에 맞는 청약만 골라 드립니다" 안내 박스.
   - **규제 면책 문구(필수·모든 추천에 일관 적용)**: 섹션 상단 경고 + **각 추천 카드마다** "**전매제한 · 실거주의무 · 투기과열지구 지정 · 특공 소득/자산기준은 시점마다 바뀝니다 — 청약홈/뉴홈 공고 원문에서 최신 확인**"을 노출한다. 이 4개 규제 항목은 정권·법 개정마다 변하므로, 한 번만이 아니라 **추천 건마다** 붙여 사용자가 어느 카드를 보든 최신확인 필요를 인지하게 한다. "1차 선별이며 자격 판정이 아님"도 함께.
1. **헤더**: "수도권 청약 주간 리포트" + 기준일 + 한 줄 요약(신규 N · 마감임박 M). KPI에 유형별 건수(`counts.by_type`) 노출.
2. **⏰ 마감 임박** (강조): `deadline_soon`을 D-day 배지 + 유형 라벨과 함께. `긴급`=빨강, `임박`=주황. 비었으면 "이번 주 마감 임박 공고 없음".
3. **📋 신규 모집공고 (유형별)**: `new_by_type`를 물건 유형별 하위 섹션으로. 순서: APT_일반 → APT_무순위잔여 → 오피스텔생활숙박 → 공공지원민간임대 → 임의공급. 각 유형 헤딩 + 카드(주택명·위치·접수기간·당첨발표·계약일·시공사·공급규모·D-day 태그). 유형별로 비면 "해당 없음".
4. **📊 지역별 경쟁률·가점**: `competition`이 있으면 표(서울/경기/인천, 평균·최고 경쟁률·가점). **비어있으면** "경쟁률·가점은 별도 서비스 연동 필요"를 안내 박스로 표기(빈 표 금지).
5. **ℹ️ 참고·주의**: `notes`(데이터 누락·인증실패·경쟁률부재·일정이상)를 눈에 띄되 과하지 않게. `others` 카운트(판별불가·수도권 외)도 여기.
6. **푸터**: 데이터 출처(청약홈 분양정보 조회 서비스), 생성 시각.

유형 라벨 표기: `APT_일반`→"APT 일반분양", `APT_무순위잔여`→"APT 무순위·잔여세대", `오피스텔생활숙박`→"오피스텔/도시형/생활숙박", `공공지원민간임대`→"공공지원 민간임대", `임의공급`→"임의공급".

## 디자인 표준
- 톤: 깔끔한 화이트 배경 + 포인트 컬러. 신뢰감 있는 리포트 느낌.
- CSS 변수:
  - `--bg:#f8fafc` `--card:#ffffff` `--ink:#1e293b` `--muted:#64748b`
  - `--urgent:#dc2626`(긴급) `--soon:#ea580c`(임박) `--accent:#2563eb`(강조) `--ok:#16a34a`
  - 카드 그림자 `0 1px 3px rgba(0,0,0,.08)`, 라운드 `12px`
- D-day 배지: 알약형, `긴급`=빨강 배경 흰 글씨, `임박`=주황, `일반`=회색.
- 반응형: `max-width:900px` 중앙 정렬, 모바일에서 카드 1열. 표는 `overflow-x:auto` 컨테이너로 감싸 가로 스크롤.
- 라이트/다크: 기본 라이트로 충분. 인쇄해도 깨지지 않게.

상세 HTML 골격(복붙용 템플릿)은 `references/report-template.md` 참조.

## 정직성 규칙
- 빈 섹션은 숨기지 말고 "해당 없음"으로 표기 — 사용자가 "데이터가 없는 것"과 "리포트가 빠뜨린 것"을 구분할 수 있어야 한다.
- `notes`(누락·오류)를 절대 생략하지 않는다.
- summary 자체가 error/빈 상태면, 빈 리포트 대신 "이번 주 데이터 수집 실패" 안내 리포트를 만든다.

## 완료 기준
- `reports/청약리포트_{date}.html` 생성, 브라우저에서 단독으로 열림
- 마감 임박이 최상단, D-day 색상 구분 적용
- 모든 섹션 존재(빈 것은 "해당 없음")
- notes 노출됨
