# 개인 청약 매칭 스킬

`profile.yaml`(개인 조건)과 분석된 청약공고를 대조해 **"내 조건에 맞는 청약"을 압축 추천**한다.
판정이 아니라 **1차 선별**이다 — 최종 자격은 공고 원문으로 확인하라는 안내를 항상 붙인다.

## 반드시 먼저 읽을 것
- `references/청약-지식베이스.md` — 자격·가점·전략·안전마진 규칙 (강의 29~32강 근거 + §8 개정 + **2026-09-05 청약홈 원문 대조 반영**)
- `references/profile-schema.md` — 프로필 필드 정의 + 파생 계산
- `references/청약홈-용어설명-원문.md` — 청약홈 용어설명 40개 원문 스냅샷(무주택세대구성원·부양가족·예치금표·소형저가주택·규제지역 1순위 제한 등). 규칙이 애매하면 여기서 원문을 인용한다.

## 입력
- `profile.yaml` (프로젝트 루트). **없으면** 매칭을 건너뛰고 그 사실을 반환(리포트에 세팅 안내).
- `_workspace/02_analyst_summary.json` (수도권 필터·유형별 정리된 공고)

## 매칭 절차

### 1. 프로필 파생 계산  (**2026 최신 규칙 = 지식베이스 §8 우선 적용**)
- **예상 가점** = 무주택기간점수 + 부양가족점수 + 통장기간점수 (지식베이스 §5). null이면 해당 항목 0 + `가점_불완전:true`.
  - **배우자 통장 합산(§8-4, 원문 "0~2년 이상")**: `spouse_account_join_years` 1년 미만 1점 · 1~2년 2점 · **2년↑ 3점**을 민영 가점에 반영.
  - 무주택기간은 **만30세(또는 그 전 혼인신고일)부터** 센다. 프로필 값이 그 기준인지 notes에 확인 요청.
- **무주택 판정(§8-2 완화)**: `household_status`가 비아파트(빌라·오피스텔) 보유더라도 **전용 85㎡↓ + 공시가 수도권 5억(지방 3억)↓**이면 무주택으로 취급. `non_apt_property`(있으면 규모·공시가) 참고, 애매하면 "원문 확인" 태그.
- **국민 vs 민영 성향**: `account_monthly_manwon>=25` 또는 `account_total_manwon>=2000` → 국민주택 1순위 후보. 아니면 민영(예치금 충족 시 추첨). **25만원 미납입자에게는 §8-1 근거로 "지금 25만원 상향" 권고**를 notes에.
- **추첨 우위**: 예상 가점 < 55 → 민영은 추첨제 중심.
- **부부 프로필**: 신혼·기혼이면 §8-4 부부 중복청약(같은 단지 함께 넣어 확률 2배)·배우자 혼인 전 이력 배제를 전략 힌트로.

### 2. 지역·면적 선호 필터
- `regions` 부분매칭(공고 위치 문자열). 비면 수도권 전체.
- `area_pref`는 공고의 `areas`(주택형별 전용면적, analyst가 통계에서 붙임)와 대조한다. ±2㎡ 허용. `areas`가 없는 공고는 필터하지 않고 `면적_미상` 태그.

### 3. 자격 매칭 (공고별)
각 공고에 대해 프로필의 `household_types`·`household_status`로 지원 가능 경로를 판정:
- **1순위 판정(청약홈 원문, 2026-09 확인)**: 공고의 `regulation.speculation_zone||adjusted_area`(API 또는 주소 폴백)로 규제 여부를 정한 뒤 — 국민: 가입 `account_join_years` ≥ (규제 2 / 비규제 1)년 **및** `account_payment_count` ≥ (24 / 12)회. 민영: 가입 ≥ (2 / 1)년 + 예치금 — `deposit_capacity_manwon` ≥ 기준표(지식베이스 §5, **신청자 거주지 `residence_area` 기준**: 서울 300/600/1000/1500, 광역시 250/400/700/1000, 경기·기타 200/300/400/500; 공고 `areas` 최대 면적 구간 적용). 규제지역에서 `household_status=무주택세대원`이거나 `won_within_5y=true`면 **2순위 강등**. **유주택(1주택·다주택)**: 국민주택은 제외, 민영은 순위 판정 후 추첨제 후보로 유지(무주택 우선 배정 뒤 잔여임을 why에 명시). 다주택은 규제지역 또는 `regulation.public_housing_zone`(수도권 공공주택지구) 민영에서 2순위. `account_type=청약부금`이면 85㎡ 초과 주택형은 제외. 미충족은 제외가 아니라 `2순위` 태그(무순위·2순위 접수는 가능).
- **특별공급 후보**: 세대유형 → 지식베이스 §3 매핑. 공통 전제 **통장 가입 6개월↑ + 무주택세대구성원**. 예: `신혼부부`→신혼특공(공공+민영), `예비신혼`→공공만, `신생아`→우선공급, `다자녀`(미성년 자녀 **2명↑**)→다자녀 특공, `노부모부양`→**세대주만**, `생애최초`→**`income_tax_years`≥5** 필요(1인가구는 60㎡↓ 전원추첨), `청년`→`is_public` 공공주택만.
  - 공고에 `models[].special`(주택형별 특공 배정)이 있으면 **내 유형의 배정세대가 실제로 있는지** 확인한다. 배정 0이면 그 경로는 제외(예: 청년·신생아는 `is_public` 공공주택에서만 배정).
- **일반공급 경로**: 공고의 `house_dtl`("국민"/"민영")을 **우선** 쓴다(API 값). 국민이면 순위+저축총액, 민영이면 가점제/추첨제(추첨 우위 여부 반영). `house_dtl`이 없을 때만 프로필 통장 성향으로 추정.
- **잔여세대(원문 대조 2026-09-06)**: `임의공급` = 통장 불필요·**유주택 가능**·재당첨제한 미적용 → 누구에게나 후보. `APT_무순위잔여`는 `house_secd`로 구분 — 무순위 = **무주택세대구성원 성년자만**(유주택 제외, 규제지역이면 재당첨제한 적용), 불법행위재공급 = 무주택세대구성원 + 일반공급은 무주택세대주 + 해당지역 거주.
- **소득 단계 판정**: 프로필 `monthly_income_manwon`·`household_size`·`dual_income`·`child_after_2023`로 지식베이스 §3 소득표(2025 도시근로자)에 따라 특공 유형×주택종류(민영/국민/공공)별 **우선/일반/추첨/초과**를 붙인다. 월소득이 없으면 `income_level` 이분법으로 근사하고 "추정" 표기. 노부모·생초·신생아는 1순위 요건(§4)과 규제지역 5년 내 당첨 여부를 먼저 통과해야 한다.
- **오피스텔/생활숙박**: 만 19세↑ 통장·주택수 무관, **특공 없음** → 특공 경로를 붙이지 않는다(주택수 산정·대출 규제는 원문 확인).
- **공공지원 민간임대**: 통장 불필요, 특공은 신혼/청년/고령자만(`models[].special`). 무주택 요건은 공고별.
- **규제 신호(APT_일반 `regulation`)**: `speculation_zone`/`adjusted_area`가 true면 "규제지역 — 전매·실거주·대출 요건 강화 가능" 경고 태그, `price_cap` true면 "분양가상한제 — 실거주의무 가능성" 태그. API 값이라 1차 신호로 쓰되, 최신 확인 문구는 그대로 유지한다(지정·해제가 잦다).
- 자격 불충족이 명확하면 제외하되, 애매하면 `자격_확인필요`로 남긴다(임의 탈락 금지).

### 4. 전략 태그 (profile.strategy_aggressive=true일 때 강조)
지식베이스 §6 신호를 공고/주택형에 태깅. analyst가 통계에서 계산한 값을 그대로 쓴다:
- **무순위/잔여/임의공급** → `줍줍(자격무관)` 태그.
- `strategy_signals[]`(주택형별 타워형·뒷알파벳·애매평형·소수세대) → `빈집털이` 태그 + 어느 주택형인지 명시("084C 뒷알파벳·6세대").
- `supply_scale ≤ 30` → `소수세대`.
- **동시분양(같은 당첨자 발표일) 그룹**: 발표일이 같은 단지가 2개 이상이면 묶어 `동시분양-택1` 안내(덜 선호 단지 빈집털이 힌트).

### 4-1. 근거 데이터 — 지난 접수 결과 (`competition[]`)
접수 종료된 같은 지역 단지의 실제 결과를 **추천 근거로 인용**한다(추정이 아니라 데이터):
- **특공 유형별 경쟁률** `result.special{유형:{alloc, req, rate}}`: 프로필 세대유형에 해당하는 유형의 rate를 같은 지역 최근 5건에서 뽑아 "노부모부양 특공은 최근 인천 5건 중 4건 미달(0.8:1)" 식으로 why에 쓴다. rate<1은 **미달 = 신청하면 사실상 당첨**.
- **당첨가점 커트라인** `result.min_lwet`: 예상 가점과 같은 지역 최근 단지의 최저당첨가점을 비교해 "가점제 현실성"을 말한다(예상 42점 vs 최저 54점 → 가점제 비현실, 추첨·특공으로).
- **미달 주택형** `result.undersubscribed[]`: 무순위/잔여 공고의 원 단지가 미달이었으면 `안전마진 주의`(인기 없는 단지일 수 있음), 반대로 원 단지 경쟁률이 높았으면 `줍줍 가치↑`.
- 데이터가 없으면(발표 전·통계 미수집) 인용하지 않고 notes에 "근거 데이터 없음"을 남긴다. 지어내지 않는다.

### 5. 수익 관점 (purpose에 시세차익 포함 시)
- 무순위/계약취소/임의공급 → `안전마진 기회(3~4년전 분양가)` 태그.
- 안전마진 확정 계산은 실거래가 비교가 필요 → 이 하네스 범위 밖. `apt-value`/`realprice-flow` 스킬로 후속 분석하라는 포인터만 남긴다(지식베이스 §7 원칙 요약 포함).

### 6. 우선순위 점수화
공고별 `fit_score`(0~100) 대략:
- 특공 자격 적중 +40 (배정세대 확인되면 +5 추가) / 국민·민영 일반공급 경로 적합 +20 / 무순위 자격무관 +15
- 지역·면적 선호 적중 +15 / 전략 태그(줍줍·소수세대·빈집털이) +10 / 마감임박(놓치면 안 됨) +10
- 내 특공 유형이 같은 지역 최근 결과에서 미달(rate<1) 경향 +10 / 예상 가점 ≥ 지역 최근 최저당첨가점 +5
- 자격 불명확 −10 / 규제지역(투기과열·조정대상) −5(경고 태그와 함께, 제외는 아님)
상위 정렬해 **"내 맞춤 TOP" 리스트**를 만든다.

## 정직성
- 강의는 2024 기준. **규제(전매·실거주·투기과열지구·소득기준)는 반드시 최신 확인**.
- **모든 추천의 `confirm` 필드에 규제 면책 문구를 일관 포함**한다(리포트에서 카드마다 노출됨):
  "전매제한 · 실거주의무 · 투기과열지구 지정 · 특공 소득/자산기준은 시점마다 바뀝니다 — 청약홈/뉴홈 공고 원문에서 최신 확인." 한 번만이 아니라 **추천 건마다** 붙인다.
- 프로필이 불완전하면 무엇이 비었는지 명시하고, 추정임을 밝힌다.
- 자격을 단정하지 말고 "지원 가능 후보 + 원문 확인"으로 표현한다.
