01

큰 그림 — '하네스'가 뭐길래

3분만 읽으면 나머지가 쉬워집니다. 하네스는 여러 AI 일꾼(에이전트)과 작업 설명서(스킬)를 엮어, 한 마디 명령으로 전체 작업이 굴러가게 만든 자동화 세트입니다. 식당 주방으로 비유하면 —

📥
1단계 · 재료 담당
collector
API에서 공고 수집
→
🔎
2단계 · 손질 담당
analyst
수도권 필터·D-day
→
🎯
선택 · 소믈리에
advisor
내 조건 맞춤 추천
→
🖨️
3단계 · 플레이팅
reporter
HTML 리포트

👨‍🍳 주방장(오케스트레이터)이 이 순서를 지휘 · 일꾼들은 _workspace/ 폴더의 파일로 배턴을 넘긴다

일꾼들은 서로 대화하지 않고 파일(JSON)로 결과를 넘깁니다. 앞 사람이 파일을 남기면 뒷사람이 그걸 읽어 이어서 일하는 "파이프라인" 방식이라, 중간 결과를 언제든 확인·재실행할 수 있습니다.

완성되면 폴더는 이렇게 생깁니다

02

우리가 헤맸던 3구간 — 그냥 건너뛰세요

처음 만들 때 진짜로 시간을 까먹은 3곳입니다. 강의에서는 답만 알려드리니 삽질을 반복하지 마세요.

헤맨 구간뭐가 문제였나✅ 정답
① MCP로 붙이려다 401청약홈을 MCP 서버로 연결하려니 계속 인증 거부. 날짜·유형 필터도 못 씀공식 API를 파이썬으로 직접 호출. MCP 안 씀
② 인증키 Encoding? Decoding?포털이 키를 2종류 주는데 어느 걸 넣어야 되는지 몰라 삽질스크립트가 4가지 방식을 자동 시도 → 아무 키나 넣어도 됨
③ 응답 필드명이 제각각주택명·마감일 필드 이름이 유형마다 다름수집가는 원본 그대로만, 해석은 분석가에게 위임
최단 경로 한 줄 요약“MCP 쓰지 말고 공식 API 직접. 키는 아무거나. 수집은 원본 그대로, 해석은 분석가가.”
03

준비물

STEP 1 · 공공데이터포털 API 키 발급

  • 공공데이터포털(data.go.kr) 가입·로그인
  • 검색창에 청약홈 분양정보 조회 서비스 검색 → 해당 서비스 클릭
  • [활용신청] 클릭 (대부분 자동 승인, 수 분 내)
  • 승인 후 마이페이지 → 활용신청 현황에서 일반 인증키 복사
헤맨 구간 ②의 답인증키가 Encoding / Decoding 두 개로 보여도 걱정 마세요. 아무거나 하나 복사하면 스크립트가 알아서 맞춥니다.

STEP 2 · 프로젝트 폴더 만들기

새 폴더(예: apt_lottery)에서 Claude Code를 켜고, 아래 2개 파일을 만듭니다.

04

두 갈래 길 — 골라서 가세요

길 A · 초스피드 (추천) — Claude에게 통째로 시키기

가장 빠른 길은 Claude Code에게 하네스를 대신 만들게 하는 것입니다. STEP 1·2를 끝냈다면 아래를 그대로 붙여넣으세요. 이 프롬프트에는 헤맨 3구간의 정답이 이미 다 박혀 있습니다.

길 B · 직접 복붙 — 파일을 하나씩

직접 만들며 이해하고 싶다면 아래 STEP 5 ~ 8의 코드박스를 각 경로에 그대로 저장하세요. Claude Code에게 “이 경로에 이 파일 만들어줘”라고 내용을 붙여넣어도 됩니다.

참고두 길의 결과는 똑같습니다. 아래 STEP들은 완성된 정답 파일이라, 길 A로 만든 뒤 검증용으로 봐도 좋습니다.
05

주방장 — 오케스트레이터 스킬

🎯 목표: 일꾼들을 순서대로 부르는 지휘자. 사용자가 “청약 리포트 만들어줘” 하면 이 스킬이 발동합니다.
06

일꾼 4명 — 서브에이전트

🎯 목표: 각 파일은 맨 위 --- 사이 정보(이름·설명·모델) + 그 일꾼의 행동 규칙. .claude/agents/ 폴더에 저장.
07

레시피 — 작업 스킬 3개

🎯 목표: 에이전트가 참고하는 상세 작업 설명서. (주방장 스킬은 STEP 05에서 이미 만들었습니다.)
참고리포트의 실제 HTML 뼈대(CSS 포함 복붙 템플릿)는 저장소의 subscription-report-html/references/report-template.md에 있습니다. reporter가 이 템플릿에 매주 값만 채워 리포트를 그립니다.
08

심장 — 파이썬 수집기

🎯 목표: 실제로 청약홈 API를 두드리는 코드. 헤맨 구간 ①·②의 답(직접 호출 + 4방식 자동 인증)이 여기 박혀 있습니다.
09

실행 🎉

먼저 수집기만 단독으로 돌려 키가 잘 먹는지 확인합니다.

수집 완료: 318건 / 유형 5개 ... 처럼 나오면 성공입니다. (서비스키 없음이면 .env 키를, HTTP 401이 계속이면 활용신청 승인 여부를 확인.)

그다음 Claude Code 채팅에 마법의 한 마디:

› 청약 리포트 만들어줘
→ collector → analyst → reporter 순서로 실행
→ reports/청약리포트_2026-07-13.html 생성. 브라우저로 열어보세요.
다시 돌릴 때매주 청약정보 업데이트 또는 청약 리포트 다시 만들어줘 한 마디면 됩니다. 리포트 디자인만 다시, 마감기준 D-5로 같은 부분 요청도 알아듣습니다.
10

(선택) 개인 맞춤 — “내 조건에 맞는 청약만”

profile.yaml(내 조건)을 만들어두면 리포트 최상단에 “🎯 내 조건 맞춤” 섹션이 붙어, 나에게 지원 가능하고 유리한 청약만 TOP으로 추려줍니다. (STEP 06에서 만든 subscription-advisor가 이때 일합니다.)

꼭 기억하세요이 추천은 1차 선별이지 자격 판정이 아닙니다. 전매제한·실거주의무·투기과열지구·소득기준 같은 규제는 시점마다 바뀌므로, 최종 판단은 반드시 청약홈/뉴홈 공고 원문에서 확인하세요.
11

자주 나는 문제

증상원인 / 해결
서비스키 없음.env의 ODCLOUD_SERVICE_KEY= 뒤에 키가 비어 있음. 키를 붙여넣기
HTTP 401 계속활용신청이 아직 승인 전이거나 잘못된 서비스에 신청. 마이페이지에서 “청약홈 분양정보 조회 서비스” 승인 확인
수집은 되는데 리포트가 비었다최근 90일 수도권 신규 공고가 실제로 없을 수 있음. --lookback-days 180으로 늘려보기
경쟁률·가점 표가 비어 있다정상. 경쟁률은 별도 서비스라 이 하네스는 미연동(리포트에도 안내됨)
Claude가 스킬을 못 찾는다파일 경로/이름 확인. .claude/agents/·.claude/skills/ 위치와 파일명 대소문자 일치
12

한 장 요약 · 치트시트

1. data.go.kr → “청약홈 분양정보 조회 서비스” 활용신청 → 키 복사
2. 프로젝트 폴더에 .env(키) + .gitignore 만들기
3. .claude/skills/apt-subscription-report/SKILL.md ← 주방장
4. .claude/agents/ 에 4명 (collector·analyst·advisor·reporter)
5. .claude/skills/ 에 레시피 (collect·analyze·report-html)
6. .claude/skills/subscription-collect/scripts/fetch_subscriptions.py ← 심장
7. 채팅에 “청약 리포트 만들어줘” → reports/*.html 완성
8. (선택) profile.yaml 만들면 “내 조건 맞춤” 추천 추가 ⏭ 헤맨 구간 스킵: MCP 말고 공식 API 직접 / 키는 아무거나 / 해석은 분석가가
데이터 출처: 한국부동산원 청약홈 분양정보 조회 서비스 (api.odcloud.kr) · 이 강의는 apt_lottery 하네스를 처음부터 재현하는 최단 경로 기록입니다.
