# 🏠 강의: Claude Code로 "수도권 청약 주간 리포트 하네스" 처음부터 만들기

> 코드를 몰라도 됩니다. **이 문서의 회색 코드 박스를 순서대로 복사 → 붙여넣기** 하면
> 매주 수도권 아파트 청약 정보를 자동으로 수집·분석해 예쁜 HTML 리포트로 뽑아주는
> "나만의 청약 비서"가 완성됩니다.
>
> 소요 시간: **약 30분** (API 키 발급 대기 제외). 준비물: Claude Code + 공공데이터포털 계정.

---

## 0. 완성본 미리보기 — 뭘 만드는가

Claude Code 채팅창에 이렇게 칩니다:

```
청약 리포트 만들어줘
```

그러면 몇 분 뒤 이런 일이 자동으로 벌어집니다:

1. 🤖 **수집가**가 청약홈 공식 API에서 최근 청약공고 수백 건을 긁어옵니다
2. 🤖 **분석가**가 그중 **수도권(서울·경기·인천)**만 골라 마감 임박순으로 정리합니다
3. 🤖 (선택) **조언가**가 *내 조건*에 맞는 청약만 추려 TOP 추천을 뽑습니다
4. 🤖 **리포트 작가**가 이걸 `reports/청약리포트_2026-07-13.html` 로 만들어줍니다

→ 브라우저로 열면 **마감 임박 빨간 배지, 신규 공고 카드, 유형별 정리**가 한눈에 보이는 리포트 완성.

이걸 **"하네스(harness)"** 라고 부릅니다. 아래에서 하나씩 만들어 봅니다.

## 1. 큰 그림 — '하네스'가 뭐길래 (3분만 읽기)

하네스는 **여러 AI 일꾼(에이전트)과 작업 설명서(스킬)를 엮어, 한 마디 명령으로 전체 작업이 굴러가게 만든 자동화 세트**입니다. 식당 주방으로 비유하면:

| 주방 | 우리 하네스 | 하는 일 |
|------|-------------|---------|
| 👨‍🍳 **주방장(오케스트레이터)** | `apt-subscription-report` 스킬 | 순서를 지휘. "너 먼저, 그다음 너" |
| 🧑‍🍳 재료 담당 | `subscription-collector` 에이전트 | API에서 데이터 수집 |
| 🧑‍🍳 손질 담당 | `subscription-analyst` 에이전트 | 수도권 필터·마감 D-day 계산 |
| 🧑‍🍳 소믈리에(선택) | `subscription-advisor` 에이전트 | 내 조건 맞춤 추천 |
| 🧑‍🍳 플레이팅 담당 | `subscription-reporter` 에이전트 | HTML 리포트로 예쁘게 |
| 📖 각자의 레시피 | **스킬(SKILL.md)** | 각 담당이 따르는 작업 설명서 |

**핵심 구조 (이 그림만 외우면 됩니다):**

```
당신: "청약 리포트 만들어줘"
        │
        ▼
┌─────────────────────────────────────────────┐
│  오케스트레이터 (apt-subscription-report)     │  ← 주방장: 순서 지휘
└─────────────────────────────────────────────┘
        │   파일로 결과를 주고받음 (_workspace/ 폴더)
        ▼
 collector ──▶ analyst ──▶ (advisor) ──▶ reporter
  수집         분석·필터     내 맞춤        HTML
   │            │            │              │
   └── 각 일꾼은 자기 '스킬(레시피)'을 보고 일함 ──┘
        │
        ▼
   reports/청약리포트_날짜.html  ← 최종 결과물
```

일꾼들은 대화하지 않고 **파일(`_workspace/` 폴더의 JSON)로 배턴을 넘깁니다.** 앞 사람이 파일을 남기면 뒷사람이 그 파일을 읽어 이어서 일합니다. 이게 "파이프라인" 방식입니다.

**폴더 구조는 이렇게 생깁니다** (미리 봐두면 복붙이 쉬워집니다):

```
apt_lottery/                         ← 프로젝트 폴더
├── .env                             ← API 키 (비밀, 커밋 안 함)
├── .gitignore
├── .claude/
│   ├── agents/                      ← 일꾼 4명 정의
│   │   ├── subscription-collector.md
│   │   ├── subscription-analyst.md
│   │   ├── subscription-advisor.md
│   │   └── subscription-reporter.md
│   └── skills/                      ← 레시피(스킬)들
│       ├── apt-subscription-report/SKILL.md      ← 주방장
│       ├── subscription-collect/
│       │   ├── SKILL.md
│       │   └── scripts/fetch_subscriptions.py    ← 수집 파이썬
│       ├── subscription-analyze/SKILL.md
│       └── subscription-report-html/SKILL.md
├── _workspace/                      ← 일꾼들이 주고받는 중간 파일 (자동 생성)
└── reports/                         ← 완성된 HTML 리포트 (자동 생성)
```

## 2. 우리가 실제로 헤맸던 3구간 — 당신은 그냥 건너뛰세요 ⏩

이 하네스를 처음 만들 때 진짜로 시간을 까먹은 3곳입니다. **강의에서는 답만 알려드리니, 삽질을 반복하지 마세요.**

| 헤맨 구간 | 뭐가 문제였나 | ✅ 정답 (그냥 이렇게 하세요) |
|-----------|--------------|------------------------------|
| ① **MCP로 붙이려다 401** | 청약홈을 MCP 서버로 연결하려니 계속 401(인증 거부). MCP 래퍼가 날짜·유형 필터를 못 씀 | **공식 API(`api.odcloud.kr`)를 파이썬으로 직접 호출.** MCP 안 씀 |
| ② **인증키 Encoding? Decoding?** | 포털이 키를 2종류(Encoding/Decoding) 주는데 어느 걸 넣어야 되는지 몰라 삽질 | 수집 스크립트가 **4가지 방식을 자동으로 시도**하게 만듦 → **아무 키나 넣어도 됨** |
| ③ **응답 필드명이 유형마다 다름** | 주택명·마감일 필드 이름이 APT/오피스텔/임대마다 제각각(`RCEPT_ENDDE` vs `SUBSCRPT_RCEPT_ENDDE`…) | 수집가는 **원본 그대로 저장**만 하고, 필드 해석은 **분석가에게 위임**. 확정 매핑은 스킬에 메모 |

> 💡 **최단 경로 한 줄 요약:** *"MCP 쓰지 말고 공식 API 직접. 키는 아무거나. 수집은 원본 그대로, 해석은 분석가가."*

## 3. 준비물

### STEP 1. 공공데이터포털 API 키 발급 (5분 + 승인 대기)

1. [공공데이터포털(data.go.kr)](https://www.data.go.kr) 가입·로그인
2. 검색창에 **`청약홈 분양정보 조회 서비스`** 검색 → 해당 서비스 클릭
3. **[활용신청]** 버튼 클릭 (대부분 자동 승인, 수 분 내)
4. 승인되면 **마이페이지 → 데이터활용 → 활용신청 현황** 에서 내 **일반 인증키**를 확인·복사

> 인증키가 `Encoding` / `Decoding` 두 개로 보여도 걱정 마세요. **아무거나 하나 복사**하면 됩니다 (헤맨 구간 ②의 정답).

### STEP 2. 프로젝트 폴더 만들기

Claude Code를 켜고, 새 폴더(예: `apt_lottery`)에서 시작합니다. 그 폴더에 아래 2개 파일을 만듭니다.

**📄 `.env`** — API 키를 넣는 비밀 파일. `여기에_복사한_키_붙여넣기`만 바꾸세요:

```bash
# 공공데이터포털 청약홈 분양정보 조회 서비스 인증키
ODCLOUD_SERVICE_KEY=여기에_복사한_키_붙여넣기
```

**📄 `.gitignore`** — 비밀·결과물을 깃에 안 올리도록:

```gitignore
# 시크릿 — 절대 커밋 금지
.env

# 개인 프로필(개인정보) — 커밋 금지
profile.yaml

# 런타임 산출물
_workspace/
_workspace_prev/
reports/

# 파이썬
__pycache__/
*.pyc
```

### 길 A. 초스피드 (추천) — Claude에게 통째로 시키기

사실 **가장 빠른 길은 Claude Code에게 하네스를 대신 만들게 하는 것**입니다. 위 STEP 1·2를 끝냈다면, Claude Code 채팅에 아래를 **그대로 붙여넣으세요:**

```
[데이터 소스] 청약홈 분양정보 조회 서비스를 MCP 말고 공식 API로 직접 호출해.

[구조] 오케스트레이터 스킬 1개 + 서브에이전트 4개(collector→analyst→reporter, 파일 기반 핸드오프).
  collector는 원본 그대로 저장만, 수도권 필터·마감 D-day 계산은 analyst가, HTML은 reporter가.
  결과는 reports/청약리포트_날짜.html 자기완결 HTML.
```

이 프롬프트에는 **우리가 헤맨 3구간의 정답이 이미 다 박혀 있습니다.** Claude가 파일들을 만들어주면, 아래 STEP 3~6의 코드박스와 대조해 확인하면 됩니다.

````markdown
# 수도권 청약 주간 리포트 오케스트레이터

collector → analyst → reporter **서브 에이전트 파이프라인**을 조율해, 수도권 아파트 청약 주간 HTML 리포트를 만든다.

**실행 모드:** 서브 에이전트 파이프라인 (파일 기반 핸드오프). 각 단계는 `_workspace/`에 산출물을 남기고 다음 단계가 읽는다.

## Phase 0: 컨텍스트 확인
1. 프로젝트 루트에 `_workspace/` 존재 여부 확인.
2. 분기: 없음→초기 실행(전체). 있음+"새로 다시"→기존을 `_workspace_prev/`로 옮기고 전체 재실행. 있음+특정 부분만→해당 단계만 재호출.

## Phase 1: 데이터 수집
`Agent` 도구로 `subscription-collector` 호출.
- 지시: `subscription-collect` 스킬의 번들 스크립트(`scripts/fetch_subscriptions.py --out _workspace --lookback-days 90`)로 5개 유형 수집, `_workspace/01_collector_*.json` 저장.
- 반환 meta의 `auth_ok`가 false면(키 미설정/401) 계속 진행하되 Phase 4에서 `.env` 키 설정을 안내.

## Phase 2: 분석·필터
`Agent` 도구로 `subscription-analyst` 호출.
- 지시: `subscription-analyze` 스킬로 `01_collector_*.json`을 읽어 수도권 필터·D-day 계산 → `_workspace/02_analyst_summary.json`.

## Phase 2.5: 개인 맞춤 매칭 (profile.yaml 있을 때만)
루트에 `profile.yaml`이 있으면 `Agent`로 `subscription-advisor` 호출.
- 지시: `subscription-match` 스킬로 `profile.yaml` + `02_analyst_summary.json` 대조 → `_workspace/03_match_personal.json`.
- 없으면 이 단계 건너뛴다.

## Phase 3: 리포트 생성
`Agent` 도구로 `subscription-reporter` 호출.
- 지시: `subscription-report-html` 스킬로 `02_analyst_summary.json`(+있으면 `03`) → `reports/청약리포트_{날짜}.html`.

## Phase 4: 사용자 보고
- 리포트 경로 + 핵심 요약(신규 N·임박 M)을 3줄 이내로 브리핑. 인증 실패·데이터 누락이 있었으면 반드시 함께 알린다.

## 데이터 전달 프로토콜 (파일 기반)
- 중간 산출물은 `_workspace/`에 `{순번}_{에이전트}_{산출물}.json`. 최종 리포트만 `reports/`.

## 에러 핸들링
- 각 Phase 실패 → 1회 재시도. 재실패 시 누락을 리포트 `notes`에 명시.
- 인증 실패 → 멈추지 않고 "데이터 수집 실패" 안내 리포트를 만들어 원인(키 미설정)을 알린다.
````

```markdown
# 청약 데이터 수집가

## 핵심 역할
청약홈 분양정보 조회 서비스(api.odcloud.kr)에서 5개 물건 유형의 분양공고 원천 데이터를 빠짐없이 긁어와 raw JSON으로 저장한다. 판단·필터링은 하지 않는다 — 수집이 유일한 책임이다.

## 작업 원칙
- **번들 스크립트 사용**: `subscription-collect` 스킬의 `scripts/fetch_subscriptions.py`를 실행. 엔드포인트를 손으로 하나씩 부르지 않는다.
- **완전성 우선**: 각 유형을 페이징으로 전량 수집. 첫 페이지만 보고 멈추지 않는다.
- **원천 보존**: API가 준 필드를 가공하지 않고 그대로 저장(유형 라벨 `_house_type`만 부가). 가공은 analyst의 몫.

## 출력 프로토콜
- `_workspace/01_collector_notices.json` — 5개 유형 통합 공고
- `_workspace/01_collector_{라벨}.json` — 유형별 원천
- `_workspace/01_collector_meta.json` — 기준일·유형별 건수·`auth_ok`·에러

## 에러 핸들링
- 인증 실패(키 없음/401): meta에 `auth_ok:false`+error를 남긴다. 성공한 척 금지.
```

````markdown
- 판별 불가: 버리지 말고 `others.unclassified` 카운트로 보존. 임의 단정 금지.

## 2. 물건 유형별 분류
`_house_type`으로 그룹핑: APT_일반, APT_무순위잔여, 오피스텔생활숙박, 공공지원민간임대, 임의공급.

- 날짜 파싱 실패는 버리지 말고 `date_unparsed:true`, D-day=null.
- `deadline_soon`에는 긴급+임박만, D-day 오름차순.

## 4. 신규 공고 선별
- 접수 시작일이 최근 7일 이내이거나 접수 예정인 수도권 공고. 유형별로 묶는다.
- 각 항목: 주택명·위치·유형·접수시작~마감·당첨발표·계약일·시공/사업주체·공급규모·D-day·태그. 날짜는 `YYYY-MM-DD`.

## 5. 경쟁률·가점 (별도 서비스 — 있을 때만)
경쟁률·가점은 분양정보가 아닌 별도 서비스. `01_collector_stats.json`이 없으면 `competition`을 빈 배열로 두고 `notes`에 "경쟁률·가점은 별도 서비스 연동 필요"를 명시. 지어내지 않는다.

## 6. 주의사항 전달
- `meta.auth_ok`가 false이거나 유형별 error가 있으면 `notes`에 담아 리포트에 노출.
````

이 하나가 실제로 청약홈 API를 두드려 데이터를 가져옵니다. **헤맨 구간 ①·②의 정답이 코드로 박혀 있습니다** (직접 호출 + 4방식 자동 인증). 그대로 복붙하세요.

**📄 `.claude/skills/subscription-collect/scripts/fetch_subscriptions.py`**

```python
#!/usr/bin/env python3
"""
청약홈 분양정보 조회 서비스(odcloud stage 37000) 직접 수집기.
5개 상세조회 엔드포인트에서 최근 공고를 페이징 병합으로 전량 수집해
_workspace/ 에 raw JSON 으로 저장한다. 필터링/가공은 하지 않는다(analyst 담당).
"""
import argparse
import datetime as dt
import json
import os
import sys
import time
from pathlib import Path
from urllib import request as urlrequest, parse as urlparse, error as urlerror

BASE = "https://api.odcloud.kr/api/ApplyhomeInfoDetailSvc/v1"

# (label, endpoint, 날짜필터 포맷) — RCRIT_PBLANC_DE 포맷이 엔드포인트마다 다름
ENDPOINTS = [
    ("APT_일반",          "getAPTLttotPblancDetail",           "dash"),   # YYYY-MM-DD
    ("APT_무순위잔여",     "getRemndrLttotPblancDetail",        "dash"),
    ("오피스텔생활숙박",   "getUrbtyOfctlLttotPblancDetail",     "dash"),
    ("공공지원민간임대",   "getPblPvtRentLttotPblancDetail",     "plain"),  # YYYYMMDD
    ("임의공급",          "getOPTLttotPblancDetail",           "plain"),
]


def load_service_key():
    key = os.environ.get("ODCLOUD_SERVICE_KEY", "").strip()
    if key:
        return key
    # 프로젝트 루트 .env 탐색 (스크립트 기준 상위로 올라가며)
    here = Path(__file__).resolve()
    for parent in here.parents:
        env = parent / ".env"
        if env.exists():
            for line in env.read_text(encoding="utf-8").splitlines():
                line = line.strip()
                if line.startswith("ODCLOUD_SERVICE_KEY="):
                    return line.split("=", 1)[1].strip().strip('"').strip("'")
    return ""


def _http_get(url, headers=None, timeout=30):
    req = urlrequest.Request(url, headers=headers or {})
    with urlrequest.urlopen(req, timeout=timeout) as resp:
        return resp.status, resp.read().decode("utf-8")


def _base_query(params):
    return urlparse.urlencode(params)


def fetch_page(endpoint, key, params):
    """인증키 형태(Encoding/Decoding)를 몰라도 '구동되는' 방식을 자동 탐색.
    아래 4가지를 순서대로 시도하고 401이 아니면 그 응답을 채택한다."""
    base_q = _base_query(params)
    attempts = [
        (f"{BASE}/{endpoint}?{base_q}&serviceKey={urlparse.quote(key, safe='')}", None),
        (f"{BASE}/{endpoint}?{base_q}&serviceKey={key}", None),
        (f"{BASE}/{endpoint}?{base_q}", {"Authorization": key}),
        (f"{BASE}/{endpoint}?{base_q}", {"Authorization": urlparse.unquote(key)}),
    ]
    last = None
    for url, headers in attempts:
        try:
            _, body = _http_get(url, headers=headers)
            return json.loads(body)
        except urlerror.HTTPError as e:
            last = {"error": f"HTTP {e.code}", "message": e.read().decode("utf-8", "ignore")[:300]}
            if e.code != 401:
                return last  # 401 외 오류는 인증 문제 아님 → 즉시 반환
        except Exception as e:  # noqa
            last = {"error": "request_failed", "message": str(e)[:300]}
    return last or {"error": "unknown"}


def collect_endpoint(label, endpoint, date_fmt, key, since_str_dash, since_str_plain):
    since = since_str_dash if date_fmt == "dash" else since_str_plain
    base_params = {
        "page": 1,
        "perPage": 100,
        "returnType": "JSON",
        "cond[RCRIT_PBLANC_DE::GTE]": since,
    }
    first = fetch_page(endpoint, key, base_params)
    if "error" in first:
        return {"label": label, "endpoint": endpoint, "error": first["error"],
                "message": first.get("message", ""), "items": [], "total_count": 0}
    total = first.get("totalCount", 0)
    match = first.get("matchCount") or 0
    per = base_params["perPage"]
    page_data = first.get("data", [])
    items = list(page_data)
    pages = 1
    while len(page_data) == per:          # 직전 페이지가 꽉 찼을 때만 다음 페이지
        pages += 1
        p = dict(base_params); p["page"] = pages
        nxt = fetch_page(endpoint, key, p)
        page_data = nxt.get("data") if isinstance(nxt, dict) else None
        if not page_data:
            break
        items.extend(page_data)
        time.sleep(0.2)                   # rate 완화
    return {"label": label, "endpoint": endpoint,
            "total_count": total, "match_count": match,
            "collected": len(items), "pages": pages, "items": items}


def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--out", required=True, help="_workspace 출력 디렉토리")
    ap.add_argument("--lookback-days", type=int, default=90,
                    help="RCRIT_PBLANC_DE 기준 최근 N일 공고 수집 (기본 90)")
    args = ap.parse_args()

    key = load_service_key()
    out = Path(args.out); out.mkdir(parents=True, exist_ok=True)
    base_date = dt.date.today()
    since = base_date - dt.timedelta(days=args.lookback_days)
    since_dash = since.strftime("%Y-%m-%d")
    since_plain = since.strftime("%Y%m%d")

    meta = {"base_date": base_date.isoformat(), "lookback_days": args.lookback_days,
            "since": since_dash, "endpoints": [], "auth_ok": True}

    if not key:
        meta["auth_ok"] = False
        meta["error"] = "ODCLOUD_SERVICE_KEY 미설정 — .env 에 키를 넣으세요."
        (out / "01_collector_meta.json").write_text(
            json.dumps(meta, ensure_ascii=False, indent=2), encoding="utf-8")
        print("ERROR: 서비스키 없음. .env 의 ODCLOUD_SERVICE_KEY 설정 필요.", file=sys.stderr)
        return 2

    all_notices = []
    for label, endpoint, date_fmt in ENDPOINTS:
        res = collect_endpoint(label, endpoint, date_fmt, key, since_dash, since_plain)
        (out / f"01_collector_{label}.json").write_text(
            json.dumps(res, ensure_ascii=False, indent=2), encoding="utf-8")
        for it in res.get("items", []):
            it["_house_type"] = label
            all_notices.append(it)
        meta["endpoints"].append({k: res.get(k) for k in
                                  ("label", "endpoint", "match_count", "collected", "pages", "error", "message")})
        if res.get("error") == "HTTP 401":
            meta["auth_ok"] = False

    (out / "01_collector_notices.json").write_text(
        json.dumps({"count": len(all_notices), "items": all_notices},
                   ensure_ascii=False, indent=2), encoding="utf-8")
    meta["notice_count"] = len(all_notices)
    (out / "01_collector_meta.json").write_text(
        json.dumps(meta, ensure_ascii=False, indent=2), encoding="utf-8")

    print(f"수집 완료: {len(all_notices)}건 / 유형 {len(ENDPOINTS)}개 / 기준 {since_dash}~")
    for e in meta["endpoints"]:
        tail = f" [ERROR {e['error']}]" if e.get("error") else ""
        print(f"  - {e['label']}: {e.get('collected',0)}건{tail}")
    return 0


if __name__ == "__main__":
    sys.exit(main())
```

## STEP 8. (선택) 개인 맞춤 추천 — "내 조건에 맞는 청약만"

`profile.yaml`(내 조건)을 만들어두면, 리포트 **최상단에 "🎯 내 조건 맞춤"** 섹션이 붙어 나에게 지원 가능하고 유리한 청약만 TOP으로 추려줍니다. (STEP 4에서 만든 `subscription-advisor`가 이때 일합니다.)

**📄 `profile.yaml`** — 아는 값만 채우고 모르면 비워두세요 (비면 "판단 보류"로 처리):

```yaml
# 개인 청약 프로필 — 값만 바꾸세요. 최종 자격은 청약홈/뉴홈 공고 원문으로 확인.
household_status: 무주택세대주       # 무주택세대주 | 무주택세대원 | 1주택 | 다주택
homeless_period_years: null          # 무주택 기간(년)

household_types:                     # 해당되는 것만 주석(#) 해제
  # - 신혼부부
  # - 생애최초
  # - 다자녀
dependents_count: null               # 부양가족 수

account_join_years: null             # 청약통장 가입 기간(년)
account_total_manwon: null           # 납입 인정액 총액(만원)
account_monthly_manwon: null         # 월 납입액(만원): 10 또는 25

income_level: 모름                   # 기준소득이하 | 기준소득초과 | 모름
regions:                             # 관심 지역. 비우면 수도권 전체
  - 서울
  - 경기
  - 인천
purpose: 둘다                        # 실거주 | 시세차익 | 둘다
strategy_aggressive: true            # 무순위·소수세대 같은 확률 전략 노출
```

이 매칭에는 청약 자격·가점·전략 지식(강의 기반)이 담긴 스킬 `subscription-match`가 쓰입니다.
개인정보라 `profile.yaml`은 `.gitignore`로 커밋에서 빠집니다.

> 전매제한·실거주의무·투기과열지구·소득기준 같은 **규제는 시점마다 바뀌므로,

## 🔧 자주 나는 문제 (트러블슈팅)

| 증상 | 원인 / 해결 |
|------|-------------|
| `서비스키 없음` | `.env`의 `ODCLOUD_SERVICE_KEY=` 뒤에 키가 비어 있음. 키를 붙여넣기 |
| `HTTP 401`이 계속 | 활용신청이 아직 승인 전이거나 잘못된 서비스에 신청. 마이페이지에서 "청약홈 분양정보 조회 서비스" 승인 확인 |
| 수집은 되는데 리포트가 비었다 | 최근 90일 수도권 신규 공고가 실제로 없을 수 있음. `--lookback-days 180` 으로 늘려보기 |
| 경쟁률·가점 표가 비어 있다 | 정상입니다. 경쟁률은 **별도 서비스**라 이 하네스는 미연동(리포트에도 안내됨) |
| Claude가 스킬을 못 찾는다 | 파일 경로/이름이 정확한지 확인. `.claude/agents/`, `.claude/skills/` 위치와 파일명 대소문자 일치 |
