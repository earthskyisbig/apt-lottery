## 부딪힌 문제와 해결 ★
> 강의 하이라이트. 증상 → 원인 → 해결 → 교훈. (상세 로그는 docs/ERRORS.md)

- **웹앱이 마감된 청약을 추천(2026-07-15).** 27건 중 17건(63%)이 이미 마감된 공고였는데 TOP 추천에 올라갔다. 원인은 D-day가 분석 시점에 계산돼 데이터에 박제된 값이었다는 것 — 스냅샷이 5일 지나자 전부 틀어졌다. 브라우저에서 오늘 기준으로 재계산하도록 수정. **교훈: 기준일이 바뀌면 틀어지는 값은 데이터에 굳히지 말고 표시 시점에 계산한다.** 돈이 걸린 화면에서 "마감된 걸 지원하라고 추천"은 최악의 오류다.
- **슬라이드 한글 전부 깨짐(2026-07-15).** `class_slide_apple` 템플릿에 `<meta charset>`이 없어 브라우저가 인코딩을 추측 → mojibake. `<meta charset="utf-8">` 추가로 해결. **교훈: 파일만 읽으면 절대 안 보이는 버그다.** 자기완결 HTML은 반드시 브라우저로 실제 렌더를 봐야 한다.
- 헤맨 3구간(MCP 401 · 인증키 형태 · 유형별 필드명 불일치)은 `docs/ERRORS.md` 참조.

## 배운 것 / 교훈

- **좋은 프롬프트는 내가 아는 답을 미리 넣어주는 것.** "청약 자동화 만들어줘"로 막연히 시키면 AI도 MCP로 붙이다 401에서 같이 헤맨다. 반면 "MCP 말고 공식 API로 직접, 401이면 헤더로 재시도"를 프롬프트에 박으면 한 번에 간다.
- **수집과 해석의 책임을 분리하면 소스가 늘어도 구조가 버틴다.** 수집 단계에서 정규화했다면 유형이 추가될 때마다 수집기를 고쳐야 했다.
- **모르는 건 폴백 체인으로 짠다.** 인증키 형태를 추측하는 대신 4방식을 시도하게 하니 "아무 키나 넣어도 동작"이 됐다.
- **실패는 화면까지 끌고 온다.** 데이터를 못 가져왔는데 멀쩡한 척 나오는 빈 리포트가 가장 위험하다.
